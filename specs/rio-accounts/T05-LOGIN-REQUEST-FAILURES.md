## Concrete evidence gap

The existing login observation retained endpoint failure booleans, while its top-level `errorKind` was classified from the helper's caught exception. A helper timeout could therefore obscure a preceding request's actual transport error. A failed callback flag alongside a network-changed helper exception did not prove which request carried that code.

The passive per-page observer now preserves at most eight distinct classified `requestfailed` events in `requestFailures`. Each record has exactly three fields: `endpoint`, `errorKind` and `afterCallbackRedirect`. Endpoints are fixed categories `document`, `providerSubmit`, `callback`, `me` or `consent`; existing exact origin/path/method checks are retained. The request kind comes independently from exact allowlisted `request.failure().errorText` tokens, never the helper exception. Unknown, absent, malformed, overlong or throwing failure information becomes `other`. Prefixes, suffixes, raw messages and lookalike codes cannot acquire a known classification.

At the request's first observed start, a private WeakMap stores only its endpoint category and whether a callback HTTP 3xx had already been observed. The failure retains that start snapshot: false before the redirect, true after it, null when no start was observed. A request that began before the callback and failed afterward remains false. Unknown start time does not become a post-callback account request. A 3xx observation is not authentication or authorization proof. Repeated start/failure events are deduplicated by request identity; unknown endpoints consume no record budget. After eight distinct classified failures, `requestFailuresOverflow` becomes true without retaining further records.

The original top-level helper `errorKind`, endpoint booleans/statuses and post-callback account lineage remain separate. The observer emits only when the login helper records a failure; successful login emits no failure annotation. Stop removes all three listeners and prevents late events or duplicate records from changing exported evidence. There are no additional network checks, fixture lifecycle actions, retries or waiting periods in the observation path.

## Privacy and regression checks

The reporter's existing sanitizer is still the only export gate. It now requires the two new fields and exact three-field nested records, fixed endpoint/request-error enums, boolean/null phases and at most eight records. Overflow true requires eight records. Old/incomplete, malformed, extra or secret-bearing fields fail closed. The annotation limit increases from 1024 to a fixed 2048 characters so the fully populated bounded shape fits; the exact boundary and one-character overflow are tested. Arrays and records are copied. No request URL, OAuth query/code, error text, timestamp, header, body, cookie value or personal account identifier is stored or exported by the new records.

Node regressions cover a late failure from before callback 303, genuine later document/account starts, unknown starts, retained endpoint identity, helper timeout versus request error, exact-code classification, poisoned accessors, duplicates/overflow, listener cleanup, nested canaries and the actual mobile reporter gate. The existing controlled browser cases additionally require exactly one document/connection-refused/false record for initial navigation and exactly one providerSubmit/connection-reset/false for the aborted provider POST. The provider case permits at most one additional me/aborted/false record together with the observed initial anonymous 401, and rejects every other record. Both keep zero unintended login work, explicit independent recovery and removal of examined expected-fault annotations.
